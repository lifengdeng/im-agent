# 实例接入与验收清单

实例由使用者自己的应用身份、模型选择、能力合同和本地工程组成。首次接入先按[本地工程接入](本地工程接入.md)跑通合成或只读能力；机器路径、业务认证、人格、真实会话与运维细节留在私有实例和受保护运行目录。

| 环节 | 完成条件 |
|---|---|
| 固定输入 | 框架与工程使用完整 Git SHA 或已核验的版本化产物；开发目录与运行根分开 |
| 身份与范围 | 应用、租户、用户、会话和群成员范围明确；群聊只受理获授权的 @ 消息 |
| 凭据隔离 | 模型、飞书与工程认证分别提供；没有复制个人登录或把秘密写入源码 |
| 工程合同 | 能力名称、输入、结果、执行边界和证据来源可核对；模型不决定身份、路径或 Shell |
| 离线链路 | 合成事件经过持久受理、工程执行、单条回复与回读；重复输入不重复执行或回复 |
| 真实验收 | 使用自己的独立测试应用和获准会话，分别核对模型、执行、回复、回读和实际平台行为 |
| 状态恢复 | 各角色保有自己的账本、去重、scope、记忆与历史合同；未知执行或投递先对账 |
| 工程升级 | 新请求使用已验证快照，已接收请求保留原绑定；候选失败继续保有旧 handler |
| 实例发布 | 按实例维护手册验证同状态升级、恢复点、唯一接收端与目标平台；不套用离线命令操作生产 |
| 验收记录 | 明确代码、工程、依赖、平台、证据与剩余限制；运行状态不写入公共 Git |

只有实际完成的项目才可记为通过。合成测试不能代替真实模型、消息平台或业务接口的验收，仓库中存在某个模块也不代表实例已启用该能力。
