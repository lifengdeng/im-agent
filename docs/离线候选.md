# 离线验证与原生执行

通用离线工具用于检查协议、注册能力、工程快照、账本与进程边界。首次体验可使用不依赖私有实例的[数字分身示例](数字分身示例.md)；接入自己的工程见[本地工程接入](本地工程接入.md)。本页介绍另有私有实例扩展时的离线兼容验证入口。

## 验证范围

- transport / worker 在容器运行，宿主 host 主动领任务；各角色使用独立 SQLite 与角色令牌。
- Registry 核对封闭输入/结果 schema、当前 actor 授权、入队时的合同与快照绑定。
- 请求、执行和交付分别去重；lease 过期或结果未知时保留状态，不自动重跑。
- 显式记忆按完整 scope 隔离，纠错与遗忘提供回执，恢复后仍应用删除凭证。
- 工程从固定发行源生成只读快照；开发目录修改不进入执行输入，新旧任务保留各自版本。
- bundle 保存经核验的源码、解释器及依赖字节，拒绝链接与目录越界；运行状态放在 bundle 外。

默认示例为 `example/echo`。可信私有工厂可以注册额外的离线能力，事件本身不能选择模块、路径、Shell 或扩大权限。Codex stdio 客户端提供初始化、thread/turn、续接、补充和中断协议；合成协议测试不等于真实模型执行验收。

## 私有实例兼容验证

实例提供依赖锁、固定基线、可信工厂与自己的离线测试，公共工具只消费协议。工程路径、业务 provider、认证和结果断言由该实例持有，不预置任何公司工程。

在干净的固定检出上准备源码外运行目录，使用 Python 3.11+ 与已就绪的 Docker Desktop Linux 引擎：

```powershell
py -3.11 -B scripts/offline_pc.py validate --private-source <private-checkout> --runtime-root <private-runtime-root> --commit <40-char-framework-sha> --instance-commit <40-char-instance-sha>
```

运行目录须已由 `windows_environment.py` 初始化。可选 `--native-project <已安装工程目录>` 只调用实例发行清单声明的可信工厂。无需私有实例的使用者直接运行数字分身示例即可。

依赖准备可以下载固定基础镜像和经哈希校验的官方 wheel。回归容器使用 `--network none`，组件联调使用独立 bridge、宿主 loopback 端口和进程级外联限制。结束时只清理本次创建的组件，保留报告和账本；不安装、重启或发布生产服务。

专用 Codex 配置与登录态独立管理。配置检查不读取或导出 `auth.json`，协议初始化不代表模型调用；业务认证不进入示例容器。离线镜像名称使用通用实例前缀，不包含个人实例名。

## 验收边界

完整业务、多轮协作、真实 provider、现场工程执行、平台消息和实例的生产升级必须分别验证。某个私有基线通过自己的回归，只证明该固定输入下的兼容性，不能替代另一平台或实例的验收。

常驻离线入口见 [PC 常驻离线部署](PC常驻离线部署.md)，通用约束见[维护与发布规范](维护与发布.md)。Docker bridge 联调和进程外联审计不等于生产网络策略；Docker internal 网络的宿主端口限制见 [Moby 说明](https://github.com/moby/moby/issues/53960)。
