# 维护与发布规范

本文件是通用框架的长期维护约定。实例仓库负责机器清单、业务回归、生产门禁和验收记录；应用代码、工程发行快照、运行数据是三个独立的版本域。

## 归属与版本

| 内容 | 维护位置 | 生效方式 |
|---|---|---|
| 通用 transport / worker / host、合同、账本 | 本仓库 | 固定框架与实例 SHA，准备不可变应用 release 后发布 |
| 人格、私有接线、业务 adapter | 实例仓库 | 与框架配对发布；实例清单固定框架 SHA |
| 实际偏好、人员别名、会话和任务 | 源码外的持久运行状态 | 由运行时按 scope 管理，不随代码回滚 |
| 可调用工程的源码与依赖 | 工程自己的发行机制 + 助手独立快照 | 合法更新成功后构建快照，发布给新执行请求 |

默认采用 feature 分支开发、提交推送、按完整 SHA 准备候选。发布记录写明来源 ref；不得把浮动分支名、`latest` 或正在编辑的目录当生产输入。是否要求 PR 由仓库协作方式决定，不附加重复用户审批。

通用源码公开使用独立干净根，旧开发历史选择离线私有保留，不新增长期在线归档库。封存 Git 历史时保存可独立恢复的 bundle、完整对象及 refs 清单，并核验全部已备份提交和固定 SHA 检出。离线 Git 恢复与生产回滚分别验收；在旧版本获取及实例取版本兼容方案完成前，保留现有私有远端，不把备份成功当作删库、重建或公开许可。

## Mac 开发到 PC

1. 先读实例维护手册，确认请求属于开发、生产部署还是只读排查；记录当前运行版本和状态来源。
2. 在 Mac 检查两个仓库的分支、已有改动和文件归属。框架更新先提交框架，再在实例清单固定目标框架完整 SHA；只更新实例时也明确其框架依赖。
3. 运行治理检查和与修改有关的测试，检查暂存区，提交推送。真实状态与凭据不用于 Git 测试 fixture。
4. PC 检查仓库身份、干净工作树、完整检出和无隐藏标志；从明确 ref 获取并检出精确 SHA，核对实例与框架配对。
5. 从 Git 导出不可变候选，固定依赖和镜像 ID，完成隔离验证。准备候选时继续由当前生产实例接单，不能把真实队列或凭据接到测试接收端。
6. 用户要求上线时，由实例生产维护流程执行：确认兼容和恢复点、停止旧接收端、收敛在途执行与交付、保存当前状态、单实例切换、真实消息回读验收。
7. 更新运行中的 active 记录及发布回执。Git checkout 或一次检查通过不代表已上线；文档发布也不切换运行时。

## 必须保留的数据

应用升级、重启或代码回滚均保留：消息去重和交付回执、worker/transport 状态卷、原生执行账本、scope 与记忆、会话和 Codex 历史、Task/产物与版本绑定、注册表 generation 和历史 handler、独立凭据与配置。备份须有一致性和恢复验证；SQLite 使用在线备份或停机一致副本，不能只复制活动 `.sqlite3` 而遗漏 WAL。

新应用继续消费当前生产状态。不能因 release ID 改变就初始化新空卷，也不能将迁机时的旧快照再次 seed 到已投入使用的生产环境。

## 回滚语义

- **代码回滚**：采用经验证的旧代码，继续使用现在的数据和投递去重。先验证旧代码能读当前 schema、注册合同、回执和 handler；不兼容则做前向修复或经过演练的数据迁移。
- **工程版本回退**：只改变新请求的默认工程快照；已接受请求和旧 Task 仍使用原合同。若有自动 follower，回退必须带持久的 hold/pin 及恢复自动跟随的规则，不能只改 active 文件。
- **灾难恢复**：只有状态损坏或丢失才恢复备份；明确恢复点、停机期间和恢复后的消息对账。它不是代码回滚。

实例发生迁机后，旧节点的数据仅是历史快照。回滚先核对当前活跃节点的新账本和唯一接收端，再按实例维护流程恢复服务，不能直接启用过期状态。

## 当前命令的边界

`resident_pc.py prepare/check` 可以准备和校验离线 release；`activate/startup/status/stop/rollback/verify` 控制的是 **offline-only resident**。生产实例须使用自己的版本化入口。

生产更新器必须理解现有状态卷、归属标签、秘密引用、host 账本和计划任务；仅改 release 字段或换镜像不足以保证兼容。缺少这样的入口时，先实现并在副本上验证，再进入上线窗口。不得把尚未实现的生产 CLI 写成可执行示例。

## 验收与发布记录

每次应用发布记录：前后框架/实例 SHA、release 与镜像 ID、工程快照及合同、当前状态卷和 host 根的保留结果、备份与兼容性证据、在途任务/未知投递处理、单接收端证明、实际 IM 聊天和只读工程查询的回读结果、回滚目标与限制。日志不回显凭据或完整聊天。

故障时先只读检查运行清单、任务与容器状态、最近任务和回执；确认自己资源的身份后再操作。禁止为了让检查通过清空队列、删除卷、伪造成功标记、覆盖用户工作区或重放未知操作。
