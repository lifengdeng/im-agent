# 架构决策

本文件记录通用框架的职责与约束。可运行的最小链路见[数字分身示例](数字分身示例.md)，用户工程接入见[本地工程接入](本地工程接入.md)。业务工程与生产实例分别维护自己的接线、认证和验收。

| 决策 | 方向 |
|---|---|
| 框架与实例 | `im-agent` 维护通用核心；实际人格、工程接线与业务权限由私有实例持有 |
| 组件 | transport 和 worker 保留容器，工程执行放在 PC 本机服务 |
| 通信 | 本机执行服务主动领取 worker 任务，不跨容器/宿主共写 SQLite |
| 模型扩展 | 对话 provider、执行 engine、工程 adapter 分别注册 |
| Codex | 专用配置、登录、thread 和 Task，不借用桌面客户端会话 |
| 工程版本 | 成功更新的发行源生成完整只读快照，开发目录修改不影响接单 |
| 版本切换 | 新任务用新版，已有业务 Task 固定原快照与合同 |
| 人格与记忆 | 版本化 persona，私聊/用户/群范围隔离，可纠错和遗忘 |
| 恢复 | 业务与投递账本独立，未知先对账，不自动重跑或重复发消息 |
| 独立运行 | 无私有工程和公司网络也能运行合成示例；真实数据和业务实现不进入通用核心 |

工程通过注册能力提供受限查询、测试、构建或其他操作。独立示例目前支持标准库 Python JSON 桥接；复杂依赖、任务 worktree 和业务写入由可信 adapter 扩展并单独验收，不开放模型选择任意路径或 Shell。
