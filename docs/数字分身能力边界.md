# 数字分身能力边界

im-agent 将飞书消息连接到使用者明确接入的本地能力。分身的归属者、提问者、执行身份和结果接收范围分别配置；人格和工作方法不扩大访问权限。

## 框架能力

| 能力 | 接口或模块 | 约束 |
|---|---|---|
| 身份与会话隔离 | `contracts.py`、`adapters.py`、`memory.py` | 按完整 actor scope 管理；owner 只表示归属，不自动授予访问权 |
| 执行与交付记录 | `ledger.py` | 离线与飞书回执分别管理；未知状态先对账，不自动重跑 |
| 工程快照与版本绑定 | `snapshot.py`、`bundles.py`、`resident.py` | 从固定发行源导出；新请求采用发布版本，已接受请求保留原绑定 |
| 持久受理 | `intake.py` | 保存受理、计划与转发状态，重复输入保持幂等 |
| 飞书接收与结果回传 | `feishu.py` | 官方 SDK 长连接、身份核对、文本回复和回读；应用及成员范围由实例提供 |
| 人格与配置 | `twin_config.py` | 校验实例身份、人格和能力声明；凭据和私有记忆由实例持有 |
| 能力选择 | `twin_planner.py` | 规则路由或 DeepSeek；只从注册能力中选择，事实由工程结果提供 |
| 本地工程桥接 | `twin_project.py`、`examples/local-project` | 单工程、1–8 项能力、标准库 Python JSON 入口；工程源码留在宿主 |

业务查询、企业认证、人员映射、平台采集器和生产维护由实例或工程 adapter 实现。接入方式见[本地工程接入](本地工程接入.md)。

## 工程与模型

便捷入口执行审阅过的可信本地程序，使用宿主账号权限，不是任意第三方代码的操作系统沙箱。复杂依赖、Node、Codex 或外部登录需要工程自己的解释器、依赖快照和 adapter。

模型只能提议能力名称，不能决定发送者、工程路径、Shell 或执行身份，也不覆盖本地工程产生的结果。默认路由用于固定示例；开放域对话、完整多轮协作及主动监控需要额外实例实现，扩展方向见[路线图](实施路线图.md)。

## 状态与升级

离线账本不能通过改配置直接作为真实渠道账本使用。每个实例持有独立配置、授权及运行根，执行、模型调用或交付未知时保留现场并对账。

框架源码版本与实例运行版本分别管理。准备新代码时保留正在服务的实例；部署需要兼容检查、当前状态恢复点和单接收端切换，详见[维护与发布](维护与发布.md)。业务工程、个人配置和运行数据无需公开。
