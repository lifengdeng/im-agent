# 数字分身能力边界

im-agent 的目标是让他人直接向一个人的数字分身提出问题，并由分身使用该人明确接入的能力完成工作。本人、请求者、执行身份和结果接收范围分别表达；人格与工作方法不扩大权限。

## 通用能力

| 能力 | 实现 | 边界 |
|---|---|---|
| 身份、租户、会话与成员隔离 | `contracts.py`、`adapters.py`、`memory.py` | 沿用完整 actor，实例 owner 仅为归属信息，不自动授予请求者访问权 |
| 执行与交付去重、未知状态 | `ledger.py` | 默认离线语义保留；显式增加独立的 Feishu 回执 profile，禁止直接混用旧账本 |
| 独立工程快照与历史绑定 | `snapshot.py`、`bundles.py`、`resident.py` | 沿用；示例按哈希核验固定工程程序与数据，原工程工作区编辑不进入运行副本 |
| 持久受理与幂等转发 | `intake.py` | 独立账本保存受理、计划与转发状态，不依赖业务数据库 |
| 飞书身份映射、文本接收、回复回读 | `feishu.py` | 通用实现使用官方 SDK 长连接和 API；不依赖实例旧 SDK 封装或公司账号规则 |
| 人格与工作方法配置 | `twin_config.py` | 提供合成实例模板及严格配置校验；实际人格、人员映射与私有记忆仍由实例持有 |
| 受限模型路由 | `twin_planner.py` | 默认确定性路由；可选 DeepSeek 只提议已注册能力，保留原始问题与发送者，最终事实来自工程结果 |
| 独立运行与演示 | `twin.py`、`scripts/digital_twin.py` | 独立目录、服务令牌和 Compose 项目；不修改其他 resident 或实例发布清单 |
| 通用工程接入 | `twin_config.py`、`twin_project.py`、`examples/local-project` | 单工程注册 1–8 项能力；固定 Git SHA 导出宿主工程快照，模型只选能力，JSON 桥接产生事实结果；工程源码不进入容器 |

业务查询、身份映射、群历史规则、私有 provider、企业认证、状态迁移和生产维护工具由实例仓库维护。通用框架通过合同和合成夹具验证，不包含使用者的业务工程。接入方式见[本地工程接入](本地工程接入.md)；工程可保持私有，不要求复用维护者的应用身份。

## 兼容与发布

旧 `Worker` / `Transport` 构造函数及 wire 协议继续支持原调用；默认回执仍只接受离线 `fake-` ID。已有离线账本不能通过修改参数自动变成真实渠道账本；示例必须使用新的独立目录。未知模型调用、执行、发送与回读均保留现场，不自动重放。

私有实例的框架 SHA 与实际运行版本独立管理。通用框架的新提交不等于实例维护器已接受新版；采用时仍须完成实例自己的兼容验证和当前状态副本演练，不放宽生产门禁。

## 后续能力

- 多轮补问、会话恢复、进度编辑与取消，通过通用合同和合成夹具分别验证。
- 将可共享工作方法与私人记忆分别装配，保留现有记忆 scope、纠错和遗忘回执。
- 为可信监控程序增加有来源、去重标识和通知范围的事件入口，复用审阅与交付账本。具体平台采集器由实例维护。
- 按工程补充复杂依赖 bundle、细分权限与发行验证；当前标准库 JSON 入口不接受模型提供任意模块、路径或 shell，也不提供现网状态迁移。

当前拟仅公开审定源码供查看与 GitHub fork，不授予额外开源许可；个人权属声明、技术来源核对和隐私边界见[公开准备审查](公开前审查.md)。实例与业务工程不随框架展示而公开。
