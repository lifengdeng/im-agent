# 创建自己的数字分身实例

初始化在框架源码外创建独立实例。默认使用合成身份、规则路由和示例工程；真实凭据、工程路径、授权回执与运行账本分别保存。不会复制已有私有实例、初始化 Git、启动常驻服务或更新其他实例。

## 先跑离线完整链路

从干净的 im-agent 仓库运行，Python 3.11+、Git 即可，无需飞书应用、模型账号、SDK 或 Docker：

请使用 Git clone 并在仓库根运行；`--commit` 必须是这个检出的完整 HEAD，工作区也须干净。下载 ZIP 或源码压缩包没有 Git 元数据，不能直接完成需要固定 SHA 的准备与演示。若代码已有本地修改，请先保存为可核验提交或另用干净检出，不用 reset 或隐藏修改来绕过检查。

```sh
python3 -B scripts/init_instance.py init --instance-dir ../my-agent-instance --defaults
python3 -B scripts/init_instance.py demo --instance-dir ../my-agent-instance --runtime ../my-agent-demo --commit "$(git rev-parse HEAD)"
python3 -B scripts/init_instance.py status --instance-dir ../my-agent-instance
```

Windows PowerShell 使用明确的 Python 版本：

```powershell
$frameworkCommit = git rev-parse HEAD
py -3.11 -B scripts/init_instance.py init --instance-dir ../my-agent-instance --defaults
py -3.11 -B scripts/init_instance.py demo --instance-dir ../my-agent-instance --runtime ../my-agent-demo --commit $frameworkCommit
```

实例目录必须是新目录，位于框架、其他仓库、凭据目录和已有实例状态之外；运行目录还必须与实例和工程分开。路径中的符号链接、Windows junction、既有实例及既有运行根都会被拒绝，失败现场保留。每次演示用新的运行目录；原目录中的账本不会被清空。

若命令拒绝既有目录，选一个新的同级目录再运行，不删除已存在的实例或账本来重试。首次应看到合成配对、`reply_count=1` 和 `readback_verified=true`；模型、真人配对及工程选择可以在离线体验之后再配置。

`demo` 先用一次性配对码、合成私聊和 loopback HTTP 回读演练配对，再运行提问 → 持久受理 → 原生宿主子进程 → 工程程序 → 单条回复 → HTTP 回读，同时检查重复事件及 transport 重建不重复发送。报告在运行根 `onboarding-report.json`：

- `passed=true`、`reply_count=1`、`readback_verified=true`。
- `pairing_scope=synthetic-only`、`live_authorization_created=false`。
- `real_feishu_messages=0`、`real_model_calls=0`、`containers_verified=false`。

此命令在本机运行合成接口，不建立飞书或模型连接，也不启动 Docker。连接真实应用前须完成下面的配置与配对，离线回执不能用于授权真实应用。

## 实例目录

```text
my-agent-instance/
  .im-agent-instance.json        # 初始化工具的目录归属标记
  instance.json                 # 默认离线配置、人格与注册能力
  instance.feishu.json           # 真实配对确认后才生成，Git 忽略
  .env.example                  # 环境变量名示意，不填真实值
  .gitignore
  README.md
  project-template/             # 可复制到独立工程的标准库桥接起点
    im_agent_project.py
    project.json
    capabilities.json
  .private/                     # 整个目录 Git 忽略
    settings.json               # 工程路径和固定 SHA、模型声明、配置版本
    feishu.json                 # App Secret
    model.json                  # 可选模型 Key
    offline-pairing.json        # 合成配对回执
    pairing.json                # 真实会话配对与本机确认回执
    credentials.env             # prepare-live 后供 Compose 使用
    live-runtime.json           # 唯一运行根绑定；失败也保留
```

Mac/Linux 的新目录为 0700，配置及凭据文件为 0600，秘密临时文件同样限制权限。Windows 在写凭据前设置当前用户和 SYSTEM 的目录 ACL。凭据保存在本机文件中，并非系统钥匙串；按实例凭据标准保管、备份，不上传截图或整个目录。工具不读取个人 Codex 登录或其他实例凭据。

## 分步填写凭据、模型和工程

移除 `init` 的 `--defaults` 即进入交互配置；已创建的实例使用：

```sh
python3 -B scripts/init_instance.py configure --instance-dir ../my-agent-instance
```

终端会依次引导 App ID / App Secret、模型配置和工程选择。秘密输入不回显；非交互终端拒绝秘密输入，避免 getpass 回退到可见输入。App ID 留空保留；工程留空保留，输入 `example` 返回内置合成工程。

模型目前支持 `rules` 和 `deepseek`。`rules` 不调用模型；`deepseek` 需要当前可用的模型名称和独立 API Key。配置时只保存参数，不连接模型；实际调用发生在收到获授权问题之后。模型只能在注册能力中选择，不能指定 actor、任意路径或 Shell。首次使用自己的模型账号时，先运行只读能力并检查回执。

选择自己的工程需要干净 Git 仓库、完整 SHA、已提交的 `im_agent_project.py` 及能力声明 JSON。初始化不会把任意工程自动改造成 adapter；先按[本地工程接入](本地工程接入.md)实现桥接。可把生成的 `project-template/` 复制到独立目录进行修改和 Git 提交。选择时只校验固定快照，不导入或执行工程代码；交互确认会列出能力及 SHA。当前便捷入口支持标准库 Python 桥接，可信程序以宿主账号权限执行。

无交互的工程选择示例：

```sh
python3 -B scripts/init_instance.py configure --instance-dir ../my-agent-instance --non-interactive --project-repository ../my-local-project --project-definition ../my-agent-instance/project-template/capabilities.json
python3 -B scripts/init_instance.py demo --instance-dir ../my-agent-instance --runtime ../my-project-demo --commit "$(git rev-parse HEAD)" --selected-project --question "检查工程版本和检查结果"
```

`--selected-project` 明确允许离线演示执行所选工程。省略时始终执行公共合成工程，不会因为填写过工程路径就自动执行真实业务。无交互脚本可用 `--app-id`、`--app-secret-env`、`--provider deepseek`、`--model`、`--model-key-env`；secret/key 参数只接收环境变量**名称**，不接收凭据值。不要在命令行、Shell 历史或源码里写真实秘密。

工程更新后需重新选择并确认新 SHA；已导出的运行版本不会自动跟随开发工作区。配置或凭据变化都会使旧配对失效。

## 真实飞书私聊配对

使用没有其他接收端的独立企业自建应用。先在飞书后台开启机器人能力、长连接事件 `im.message.receive_v1`，设置应用可用范围，授予接收私聊、机器人发送及消息回读权限并发布生效，详见[权限表](本地工程接入.md#4-接入自己的飞书应用和模型)。初始化不能替你创建应用、授予管理员权限或发布应用。

配对主机需要可选的锁定 SDK；在独立工具环境安装，无需改变全局 Python：

```sh
python3 -m venv ../im-agent-setup-tools
../im-agent-setup-tools/bin/python -m pip install --require-hashes -r requirements-feishu.lock
../im-agent-setup-tools/bin/python -B scripts/init_instance.py pair --instance-dir ../my-agent-instance --connect
```

Windows 将工具解释器换成 `../im-agent-setup-tools/Scripts/python.exe`。SDK 长连接在受时限约束的子进程中运行，后台子进程使用 Windows 隐藏启动选项；交互配对本身在终端进行。

工具只读获取本应用机器人信息，在本机显示随机一次性码。默认 300 秒有效，可用 `--timeout 30..600` 调整。在该应用私聊发送 `/pair <一次性码>`。只有正确应用、租户一致的真人私聊、会话开始后创建的文本和正确码才进入核验；读取原消息后比对发送者、会话和文本，第一条合格候选固定，其他事件不执行业务。消息读取权限不足时无法授权。

收到候选后先停止配对接收端，再在本机列出完整用户/会话、模型和工程能力。输入 `YES` 才写入真实授权，其他输入拒绝。配对过程不回复消息、不调用模型、不执行工程。授权只覆盖本次私聊，不自动授权群聊或整个租户；有效配对码的私聊参与者仍需由本人在本机核对。回执不保存明文码。

超时、失败或取消均保留会话记录，之后可以重新配对。授权确认后，真实配置使用新的接收时间下界，排除配对消息及更早积压消息。后续修改人格、工程、模型或凭据都需要重新配对。

## 生成待启动的独立运行版本

真实配对完成后才允许：

```sh
python3 -B scripts/init_instance.py prepare-live --instance-dir ../my-agent-instance --runtime ../my-agent-live --commit "$(git rev-parse HEAD)"
```

此步骤导出固定框架与工程 SHA、分开的 worker/transport/host 账本和角色凭据、Compose 配置；不启动进程。App Secret 只供 transport，模型 Key 只供 worker，宿主执行器不需要它们。启动方式沿用[独立示例的容器与宿主步骤](数字分身示例.md)，Compose 额外使用 `--env-file <实例绝对路径>/.private/credentials.env`，宿主运行导出源码入口。示例不是任何既有私有实例的生产发布指令。

工具在准备前写入唯一运行根绑定，之后阻止这个实例再配置、再配对或创建第二套新账本；跨进程有实例设置锁。准备失败也保留绑定与现场，需要核对该运行根后按实例维护流程处理，不删除状态重试。该保护仅约束同一实例目录，无法检测另一台机器或另一实例是否使用同一个 App ID，操作者仍须确保一个应用只有一个接收端。

后续升级、迁机、解绑、当前账本保全和生产回滚由实例维护流程负责。初始化不管理现有实例，也不会修改其计划任务、容器、代码或运行状态。

## 运行约束

便捷工程入口支持标准库 Python JSON 桥接；复杂依赖、业务认证和外部工具由工程自己的 adapter 管理，详见[本地工程接入](本地工程接入.md)。模型用于选择能力，工程程序负责结果和依据。

首次连接自己的飞书应用时，等 transport、worker 和宿主就绪后再发送一条只读请求，检查受理、模型选择、执行、回复和回读记录。不要把历史聊天手工转换为事件重放；请求或投递状态未知时先对账，不清空账本重试。

此入口创建独立实例，不提供完整多轮补问、业务状态迁移或现有实例的升级命令。群聊、复杂工程和长期运行按各自的身份范围与实例维护流程配置。
