# 公开准备审查

当前决定更新于 2026-10-25。维护者已确认通用框架为个人设计、版权归个人，除维护者自己的贡献外没有其他人员贡献；公司业务工程不纳入公开范围。项目暂不采用开源许可证，未来仅准备审定源码的公开查看和 GitHub fork。当前开发库仍为私有，没有执行公开或历史改写。

## 已确认的边界

| 事项 | 当前决定 |
|---|---|
| 权属 | 按维护者的个人权属声明记录，已关闭“等待维护者确认”项 |
| 人员贡献 | 按维护者声明，没有其他人员贡献；第三方依赖仍单独保留其许可边界 |
| 公司工程 | 工程实现、私有 SDK、业务数据、账号及实例接线保持私有，通用框架不包含这些内容 |
| 项目许可 | 暂不授予额外开源许可，不添加 Apache-2.0、MIT 或其他项目许可证 |
| 公开方式 | 未来从审定源码建立干净公开发行根，不能直接把当前开发库及其旧 refs 转为 public |
| 开发记录 | 既有提交、作者邮箱、分支、历史 CI 日志和原始审查证据继续私有保留 |
| 历史保留方式 | 维护者选择本机离线私有备份，不新增长期 GitHub 归档仓库；对外仍以 `im-agent` 为目标名称 |
| 个人邮箱 | 不公开；本仓库后续提交已配置 GitHub ID-based noreply，未修改全局或实例仓库配置 |
| 实例与生产 | 实例仓库保持私有，框架整理不更新其版本绑定或生产进程 |

无开源许可证的公开仓库仍适用 GitHub 提供查看和 fork 所需的平台条款，不因此额外授予一般商业使用、再分发或其他开放源代码许可。[GitHub 许可说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)、[GitHub 服务条款 D.5](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#5-license-grant-to-other-users)

## 技术来源核对

个人权属来自维护者声明；以下技术核对用于确认代码边界，两者分别记录：

- 检查候选框架的导入、锁文件、配置、工具入口与合成示例，未发现公司工程实现、私有 SDK、内部服务默认地址或真实业务配置。
- 对照本机可读取的 5 个相关参考仓库，共 4,073 个文本文件；连续 8 个去空白非空行且至少 180 字符的块匹配为零。
- 对 Python 函数另作去位置属性的 AST 等同性比较，至少 100 个 AST 节点的大型函数匹配为零。
- 非标准库外部 Python 依赖为官方飞书 SDK；其他本地导入可在框架源码中解析。可信实例工厂是显式扩展接口，不是内置公司实现。
- 既有私有全历史、对象与日志检查没有确认的凭据泄漏；原始定位、参考仓库版本与开发记录只保存在私有证据中。

相似性检查有明确阈值，不能证明所有可能的来源均不存在；本次没有发现需要继续按公司代码处理的具体文件，不再把泛化的权属疑问列为硬阻塞。机器可读的当前边界与依赖证据见[公开审查清单](公开审查清单.json)。

## 当前文件整理

开发规范使用本仓库自己的跨平台约定；实例接入、架构与路线图按通用能力组织。文档和示例不以特定服务器、公司工程或个人实例为运行前提。过去的迁移计划、冻结业务清单、开发阶段代号及提交时间线不作为未来公开材料。

源码、运行状态、凭据和工程快照仍分别维护。状态迁移、备份、旧合同与未知执行处理是实例升级需要的通用约束，继续保留，不能为清理文档而删去恢复和去重规则。

## 干净快照与新手接入审查

候选只从干净、固定的 Git 提交树导出，不复制工作目录或 `.git`。供查看的压缩包重新打包文件，规范化归档用户名、目录前缀和时间，不携带 `git archive` 的原提交 comment。内容清单保存文件哈希、模式及压缩包哈希；原开发 SHA、历史扫描定位和参考仓库信息只留在私有审查材料中。

独立本地候选仓库重新初始化，仅创建一个初始根提交，不设置 remote，不导入旧 refs、对象、reflog 或配置。公开时只消费这份审定文件树和新根，不能直接把带旧历史的开发库切为 public，也不能把强推新根当作旧记录已彻底清除。

历史保留方式已选择离线私有备份；日常仍是通用框架与私有实例两个 GitHub 仓库，不新增长期在线归档库。离线材料包括独立 Git bundle、完整对象与 refs 清单、reflog 及可访问的远端发布记录，须经过恢复核验。Git 历史备份不包含实例运行账本、生产凭据或完整生产恢复能力；无法读取或不能导出的远端资料必须单独列出。

后续同名干净库切换需要另行准备和授权。在确认旧 SHA 的离线获取、实例取版本方式、恢复点以及远端重建范围之前，保留现有私有远端及其历史，不删除、重建或公开。备份成功本身不等于已演练生产回滚。

新手默认入口已明确 Git clone、Python 3.11+、干净完整 SHA、新的源码外目录，以及离线无需凭据、SDK 和 Docker。CI 从归档文件重新建立单提交的合成根，再运行内置与独立工程的初始化和离线全链路，检查旧开发提交对象不可获取；覆盖 Linux / Windows、Python 3.11 / 3.13。该流程不调用真实飞书、模型或业务工程。

## 公开前剩余阻塞项

| 事项 | 处理边界 |

| 明确授权远端重建与公开 | 本次只授权离线备份，未授权删除、重建或公开远端；实际切换单独执行。 |

旧远端的 Packages 盘点曾因缺少读取权限返回 403，不能记为“没有产物”，也不能声称已离线封存。此限制不阻塞源码候选，但在任何远端删除或重建前必须确认其处理范围。个人权属、不添加项目许可证及离线保存历史均按维护者已确认的决定处理，不重复列为待拍板项。

标准库桥接、受限模型选择和单人私聊是当前已验收的首版范围。复杂依赖、Windows 真实业务工程、群聊、持续值守及生产升级须分别验收，属于明确能力边界，不冒充本次源码公开的必备功能。

现有私有开发库在切换前继续保留完整历史和可获取的版本，离线档案单独私有保管。任何远端删除、重建、公开、仓库迁移或历史重写均另行执行。新增版权许可也须由维护者明确决定。本轮没有访问生产主机、发送消息或调用真实模型。
