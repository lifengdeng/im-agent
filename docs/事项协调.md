# 事项协调：P0–P3

`im_agent.work` 提供与渠道、模型、工程无关的事项记录和受限路由。实例在自己的 worker 数据库中显式接入；现有数字分身便捷入口不自动启用它。执行事实继续由 `ledger.Worker/Host` 持有，交付事实继续由 transport 回执持有。

## 身份与记录

- 事项 ID 表示持续的目标；输入 ID 表示一次已验真消息；job / execution 表示一次实际执行。这些 ID 不互相替代。
- `work_items` 保存完整 actor、可信 thread key、原始事件、受理时的授权合同和会话 job 引用。
- `work_inputs` 保存一次性路由决定与控制回执。重投同一输入不能改变目标或重新生成决策；改变内容、目标或操作会被拒绝。
- `work_runs` 关联已经受理的执行及其不可变 binding；`work_links` 关联已经验真的工程 Task / thread 或交付引用。引用不授予新的执行权限。
- `work_grants` 保留原注册声明。读取或续接先检查当前权限，再核对历史合同；名单扩大不会丢失仍合法的历史事项，撤权后不能靠旧合同继续访问。

所有记录位于运行状态，不进入源码。`install(db)` 只在初始化阶段调用；`WorkItems.receive` 与实例受理记录必须在同一 worker 事务中提交。连接应提供 `sqlite3.Row`；不把这套数据库交给宿主执行器共写。

## 路由边界

可信实例将输入归类为 `request/continue/status/stop`，并提供经校验的 thread key 和 job 引用。模型不能决定 actor、路径、Shell 或授权范围。

新请求新建事项。续接只接受同一完整 actor、同一 thread、同一项目和能力下的明确引用；无引用的状态或停止要求该范围内恰好一个活动事项。歧义返回 `clarify`，未知执行返回 `reconcile`，不会据此再分发业务。已结束事项不自动重开；新的执行须由显式授权流程接入。

通用库不判断自然语言是否扩大了业务目标，也不决定企业身份映射。实例和 adapter 仍须校验能力输入、业务权限及接收范围。

## 异步与控制

`Pending.poll()` 是可信执行边界：没有结果时立即返回 `None`，有结果时返回经 adapter 校验的值；`wait()` 保留同步调用方式。实例负责持久提交、检查点、唤醒和恢复，不能仅凭一个内存 Future 声称可恢复执行。

`Worker.claim_guard` 可由可信组合根接入父事项检查。拒绝领取的请求保持原账本状态，调度继续检查其他请求；guard 不得调用模型或执行工程。它不扩大注册能力，也不替代既有 binding 校验。

`Worker.cancel_queued(job, parent)` 只能原子取消尚无 execution 的内部排队请求。已经被领取、结果未知或 parent 不匹配的请求不能走此路径。运行中的停止仍须经过执行引擎协议和真实确认。

控制回执区分受理、排队、送出、接受、拒绝和未知。停止确认不等于执行结果或消息交付成功。未知回执不能被普通观察改写；`reconcile_receipt` 仅供可信维护代码在核验具体证据后做带证明哈希的记账，不暴露为模型工具。

## 兼容与验证

`im_agent.work_events` 提供不可变来源事件、多对多显式订阅和上下文引用。实例注册来源权限检查器；每次订阅、召回和续读先检查完整 actor、当前事项权限、来源权限及订阅。事件只补充参考资料，不创建执行，不改变目标和授权。摘要默认控制在 4096 UTF-8 字节内，最多八条；正文单条不超过 16 KiB，`read` 分页续读，每次最多 2000 字符。关联引用也须逐项授权，不沿链接传播权限。

`im_agent.work_runtime.Resources` 由可信 adapter 声明资源键，调用方在 `BEGIN IMMEDIATE` 内原子领取。独立事项在并发预算内可并行；同事项和共享资源互斥。unknown 仍占位，不能通过新 run 绕过；释放未知锁需要维护端核验后的证明哈希。此模块不启动进程，不替 adapter 决定哪些环境可以并发。

`Proactive` 消费组合根提供的版本化规则，支持 off / shadow / enabled、每小时预算、幂等候选及固定能力。候选领取后先持久记 running，再执行已注册能力。当前规则不匹配则拒绝；启动恢复把在途候选记 unknown，不自动重放。实例负责来源验真、按状态合并、收件人、安静策略、具体只读能力和投递回执。

`Watchdog` 只观察调用方提供的真实状态和有语义的检查点，不把轮询、心跳或更新时间当进展。只在停滞、待认证、结果待核对及恢复时返回一次状态变化；不授权修复、重跑或投递。实例必须保留异常现场并决定哪些观察可以产生候选事项。

规则可显式设置 `budget_scope: "case"`，按可信调用方提供的事项 case key 计算每小时预算，避免独立事项相互消耗通知额度。省略时仍按整条 policy 计数，保留旧规则语义；unknown 候选仍计入原预算。收件人、来源、原消息锚点与投递去重由实例逐次校验，不能仅凭 case key 决定授权。

`Worker.capability_additions` 是可信组合根的显式新能力映射，用于版本化合同演进。缺省仍禁止能力集合变化；声明旧能力到新能力的映射后，仅允许在相同项目、完整 actor 和 group scope 下增加能力，旧策略不得同时改变。历史合同和已排队 binding 保留，generation 增加一次。它不是远程发布接口，也不能让模型新增工具。

事项表为显式接入的附加表，不改原消息、租约、scope、执行 binding、记忆及交付去重。历史执行和旧 handler 保留原协议。实例升级还须验证状态兼容、历史合同和单接收端切换；本模块不提供生产发布许可。

`tests/test_work.py`、`tests/test_work_events.py`、`tests/test_work_runtime.py` 使用合成身份验证事务、幂等、撤权、范围、事件预算、资源互斥、未知锁对账、规则预算、重启和真实进展判断。具体渠道、交付和业务恢复须由实例另行验证。
